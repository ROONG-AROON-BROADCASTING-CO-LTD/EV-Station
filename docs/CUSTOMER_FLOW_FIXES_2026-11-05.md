# ผลแก้ไข customer flow — 5 พฤศจิกายน 2569

สถานะ: แก้และทดสอบในเครื่องบน branch `Dev` (ฐาน commit `99e8f78`) ยังไม่ได้ commit, deploy หรือรัน migration บน production ชุดทดสอบใช้ข้อมูลจำลอง ไม่ส่ง OTP/LINE/Gemini จริงในรอบนี้ และไม่ได้ย้อนงานแก้ถนนกับการประเมินหลักฐานที่ค้างอยู่เดิม

## พฤติกรรมที่เปลี่ยน

1. **Gemini สรุปคำแนะนำล้มเหลวชั่วคราว** — ลองสูงสุด 3 ครั้งในกรอบ timeout เดิม มี backoff/jitter และเคารพ Retry-After สำหรับ 408/429/500/502/503/504 และ network error ที่เข้าข่าย ไม่ลองซ้ำทันทีสำหรับรหัสผ่าน/สิทธิ์ผิดหรือ JSON ผิด รายงานหลักยังใช้ได้ด้วยข้อความสำรอง หน้าเจ้าหน้าที่ลองกู้คำแนะนำสำรองอีกหนึ่งรอบหลัง cooldown 60 วินาทีต่อรายงาน/ภาษา ไม่วนไม่สิ้นสุด ลูกค้าและสิทธิ์อ่านอย่างเดียวไม่กระตุ้นงาน AI ที่เสียค่าใช้จ่าย
2. **หน้ารายละเอียดพื้นที่ไม่เห็นรายงานที่เสร็จแล้ว** — โหลด latest report แล้วแสดงปุ่มเปิดรายงานตรงหน้านี้ เมื่อยังไม่มีรายงานจะตรวจทุก 30 วินาที สูงสุด 5 นาที และมีปุ่มตรวจอีกครั้ง; สถานะผิดพลาดแยกจากยังไม่มีรายงาน
3. **OTP** — แสดงอีเมลและเวลาส่ง เพิ่มส่งรหัสใหม่พร้อมนับถอยหลัง 60 วินาที ป้องกันกดซ้ำ และแจ้งรหัสผิด/หมดอายุ/ส่งไม่สำเร็จ โดยคง rate limit ฝั่ง server
4. **LINE OA** — เพิ่ม Settings เฉพาะเจ้าของสำหรับจับคู่แชตเจ้าหน้าที่กับ OA ด้วยคำสั่งครั้งเดียว อายุ 10 นาที ตรวจลายเซ็น webhook ก่อนรับข้อมูล ไม่ใช้ผู้รับเก่าที่ไม่ได้รับอนุมัติ มีปุ่มทดสอบและสถานะตอบรับ LINE รายละเอียดใน [คู่มือตั้งค่า](LINE_NOTIFICATIONS_SETUP.md)
5. **PDF** — ดาวน์โหลดไฟล์โดยตรงใน browser ไม่เปิดหน้าพิมพ์ ใช้ข้อมูลที่แสดงและตรวจสิทธิ์แล้ว รอข้อมูลจำเป็น/AI ที่กำลังสร้าง เก็บค่าสถานะอินเทอร์เน็ตและคำแนะนำที่เลือกจริง ไม่คืนค่าคะแนนหลักฐานที่ยังยืนยันไม่ได้ กรณีแพ็กเกจว่างหรือไม่ทราบขนาดพื้นที่ไม่สรุปว่าที่ดินเล็กเกินไป

PDF เป็นรายงานข้อความและตาราง พร้อมพิกัดและลิงก์ Google Maps; ภาพประกอบยังดูบนเว็บ มีข้อความระบุใน PDF ใช้ pdfmake 0.3.13 แบบโหลดเมื่อกดดาวน์โหลด พร้อมฟอนต์ IBM Plex Sans Thai ที่แนบ OFL และตัดคำไทยก่อนจัดหน้า ไม่มีการส่งข้อมูลรายงานไปบริการสร้าง PDF ภายนอก

## ข้อจำกัดและสิ่งที่ต้องทำเมื่อขึ้นระบบ

- ยังไม่ได้ยืนยัน Gemini/SMTP/LINE สดในรอบนี้ การลองใหม่ไม่สามารถรับรองว่าผู้ให้บริการภายนอกจะกลับมาได้เสมอ
- ต้องรัน migration `000027_line_recipient_approval` พร้อมการ deploy API รุ่นใหม่
- เจ้าของต้องสร้างคำสั่งใน Settings แล้วส่งในแชตเจ้าหน้าที่กับ OA หรือกลุ่มที่ได้รับอนุญาต จากนั้นทดสอบและตรวจรับจริง ชื่อ OA อย่างเดียวไม่ใช่ recipient ID
- รหัสจับคู่ที่ยังไม่ใช้เก็บในโปรเซส รองรับการติดตั้ง API หนึ่ง replica ตามระบบปัจจุบัน; เพิ่ม replica ต้องย้ายรหัสไป shared store
- `go test -race` รันไม่ได้ใน image ที่มีอยู่เพราะไม่มี gcc; ไม่อ้างว่าผ่าน race detector
- Build มีคำเตือน annotation ของ zod และ chunk เกิน 500 kB; PDF engine แยก dynamic chunk 787 kB (gzip 295 kB) โหลดเมื่อสั่งดาวน์โหลด ไม่บังคับโหลดตอนเข้าหน้าแรก
- ผล audit และชุดทดสอบไม่ใช่การรับรองว่าทั้งระบบไม่มีช่องโหว่หรือ production พร้อมทุกด้าน
