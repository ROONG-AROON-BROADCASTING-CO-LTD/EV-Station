# การแจ้งเตือนเจ้าหน้าที่ผ่าน LINE OA

LINE OA ของ RBC เป็นผู้ส่งข้อความ ส่วนปลายทางเป็นแชตของเจ้าหน้าที่กับ OA หรือกลุ่มเจ้าหน้าที่ที่เชิญ OA เข้าไปแล้ว จึงไม่ใช้ชื่อ `@บัญชี` ของ OA เป็นรหัสผู้รับ

## ตั้งค่าครั้งแรก

1. ตั้ง `LINE_CHANNEL_ACCESS_TOKEN` และ `LINE_CHANNEL_SECRET` ที่เซิร์ฟเวอร์เท่านั้น เปิด Use webhook ใน LINE Developers ให้ชี้ที่ `/api/v1/line/webhook` บนโดเมนระบบ
2. รัน migration `000027_line_recipient_approval` ก่อนเริ่ม API รุ่นใหม่ แถวปลายทางเก่าจะยังไม่ถือว่าได้รับอนุมัติ
3. เข้าระบบด้วยเจ้าของ (`super_admin`) เปิด **ตั้งค่า → แจ้งเตือนเจ้าหน้าที่ผ่าน LINE**
4. เพิ่ม OA เป็นเพื่อน หรือเชิญ OA เข้ากลุ่มเจ้าหน้าที่ หากใช้กลุ่ม ต้องเปิด Allow bot to join group chats ใน LINE Developers ด้วย
5. กด **สร้างคำสั่งเชื่อมต่อ LINE** คัดลอกแล้วส่งในแชตที่ได้รับอนุญาตให้รับข้อมูลลูกค้าเท่านั้น คำสั่งใช้ครั้งเดียวและหมดอายุใน 10 นาที ไม่โพสต์คำสั่งลงกลุ่มสาธารณะหรือรายงาน
6. รอหน้าเว็บแสดง **เชื่อมปลายทางแล้ว** แล้วกด **ส่งข้อความทดสอบ LINE** ข้อความทดสอบไม่มีข้อมูลลูกค้า ตรวจว่าได้รับในแชตที่ตั้งใจไว้ด้วย การตอบรับ API ไม่ใช่ใบยืนยันว่าเจ้าหน้าที่อ่านข้อความแล้ว

เมื่อเชื่อมสำเร็จ จะเก็บปลายทางที่อนุมัติไว้ในฐานข้อมูลและใช้ต่อหลังรีสตาร์ต หากมี `LINE_NOTIFICATION_RECIPIENT_ID` กำหนดไว้ที่เซิร์ฟเวอร์ ค่านั้นมีลำดับก่อนและหน้าเว็บจะไม่อนุญาตให้จับคู่ทับ

## ขอบเขตและการแก้ปัญหา

- ก่อนเชื่อมปลายทาง ลูกค้ายังส่งพื้นที่ได้ แต่จะไม่มีข้อความแจ้ง LINE
- การเข้ากลุ่ม, webhook ที่เซ็นถูกต้องเพียงอย่างเดียว, รหัสผิด/หมดอายุ/ใช้ซ้ำ ไม่สามารถเปลี่ยนผู้รับข้อมูลได้
- รหัสจับคู่ที่ยังไม่ใช้และสถานะการส่งครั้งล่าสุดเก็บเฉพาะในโปรเซส API ปัจจุบัน หลังรีสตาร์ตให้สร้างรหัสใหม่ ส่วนปลายทางที่อนุมัติแล้วไม่หาย การติดตั้งปัจจุบันใช้ API หนึ่ง replica; หากเพิ่ม replica ต้องย้ายสถานะรหัสจับคู่ไป shared store ก่อน
- การสร้างรหัสใหม่ยกเลิกรหัสเก่าทันที ระหว่างรอจับคู่ใหม่ ปลายทางที่อนุมัติเดิมยังทำงาน
- หากไม่ได้รับ webhook ให้ตรวจ Use webhook, URL/HTTPS และบอตอยู่ในแชตหรือกลุ่มนั้นจริง
- หาก LINE ไม่รับคำขอส่ง ให้ตรวจ channel access token, สมาชิกบอต, สิทธิ์และโควตาข้อความ หน้าเว็บจะแสดงว่าคำขอส่งล่าสุดสำเร็จหรือไม่ โดยไม่เปิดเผย token หรือ ID ผู้รับเต็ม

## หลักฐานทดสอบในเครื่อง

- Go: ทดสอบ signature, owner authorization, รหัสผิด/หมดอายุ/ใช้ซ้ำ/ยกเลิก, การคงปลายทางหลังสร้าง service ใหม่, การไม่ใช้ปลายทางเก่าที่ไม่มีการอนุมัติ และข้อความทดสอบไม่มีข้อมูลลูกค้า
- Frontend: ตรวจสถานะ, สร้าง/ยกเลิกรหัส, ไม่ส่งข้อความอัตโนมัติ, แจ้งส่งสำเร็จ/ไม่สำเร็จ และซ่อนการตั้งค่าจากบทบาทอื่น
- PostgreSQL แยกสำหรับ QA: ทดสอบ migration up/down/up และยืนยันว่าไม่อนุมัติข้อมูลเก่าอัตโนมัติ ไม่ใช้ฐานข้อมูล production

อ้างอิง: [LINE webhook signature](https://developers.line.biz/en/docs/messaging-api/verify-webhook-signature/) และ [การใช้ Messaging API ในกลุ่ม](https://developers.line.biz/en/docs/messaging-api/group-chats/)
